
__Cours sur Docker__

Docker permet d'exécuter une application dans un conteneur indépendant des machines
sur lesquelles elle a été développée, avec son propre environnement de travail.
Cela permet de lancer l'application depuis n'importe quelle machine équipée de Docker,
la rendant portable sur de nombreux environnements différents.
Docker partage tout de même le noyau du Système d'Exploitation la machine hôte.

Son Image est un modèle immuable servant à créer des conteneurs.
Un conteneur est instance en cours d'exécution d'une image.

.Configurer le Docker :
    Dockerfile (Automatise la création d'image) :
        FROM:       Débute une nouvelle étape de construction (stage) depuis une base
        WORKDIR:    Répertoire de travail
        ENV:        Définit des variables d'environnement
        ARG:        Définit des variables pour la construction de l'image
        COPY:       Copie des fichiers de la machine vers l'image
        RUN:        Lance une commande et crée une nouvelle image en résultant
        CMD:        Commande exécutée par défaut au lancement du conteneur
        EXPOSE:     Ports réseau à écouter à l'exécution (documentation !)

.Créer l'image immuable :
    > docker build -t <name> .
        -t : tag
        .  : chemin du build context du docker

.Ignorer des dossiers/fichiers :
    .dockerignore

.Lister les images :
    > docker images

.Supprimer une image :
    > docker rmi <imgID>

.Lancer un conteneur à partir d'une image :
    > docker run -d \
        -p 8090:80 \
        --name <name> \
        --network <nw> \
        -e <var>=<val> \
        <img>

    -d (daemon)      : lance en arrière-plan
    -p <HOST>:<CONT> : map un port entre la machine HOST et le conteneur CONT
    --network <nw>   : associe un réseau Docker au conteneur
    --name <name>    : donner un nom au conteneur
    -e <var>=<val>   : applique la variable d'environnement var avec la valeur val

.Lister les conteneurs :
    > docker ps -a
        -a : liste aussi les conteneurs inactifs

.Interrompre un conteneur :
    > docker stop <ID>

.Redémarrer un conteneur arrêté :
    > docker start <ID>

.Redémarrer un conteneur actif ou arrêté :
    > docker restart <ID>

.Suivre les logs d'un conteneur :
    > docker logs -f <containerID>
        -f : en temps réel

.Afficher des informations sur un conteneur :
    > docker inspect <containerID>

.Supprimer un conteneur arrêté :
    > docker rm <containerID>

.Récupérer une image depuis un dépôt d'images :
    > docker pull <img>

.Envoyer une image à un dépôt :
    > docker push <img>

#2 - Bind mounts

Les bind mounts permettent de lier un dossier de la machine hôte avec un
dossier du conteneur.

Remplacer CMD ["npm", "run", "start"] par CMD ["node", "--watch", "src/index.js"]
dans Dockerfile permet de lancer le conteneur avec un redémarrage dynamique de
l'application après modification.

.Partager des données entre l'hôte et le conteneur (bind mounts) :
    > docker run -d -p 8090:80 -v <hostpath>:<dockerpath> web

#3 - Volumes Docker

Les volumes permettent de partager des données entre le docker et l'hôte en étant
natifs de Docker, et donc plus portables que les bind mounts. Ils peuvent également
être associés à plusieurs conteneurs différents.

.Créer un volume :
    > docker volume create <name>

.Lister les volumes :
    > docker volume ls

.Supprimer un volume :
    > docker volume rm <name>

.Inspecter un volume :
    > docker volume inspect -f <outputFormat> <name>
        -f : format de sortie (ex: 'json')

.Lancer le conteneur en montant son volume :
    > docker run -v <volume>:<dockerpath> <img>

#4 - Réseau Docker

Un réseau virtuel Docker permet à différents conteneurs de communiquer entre eux
en utilisant leurs noms.

.Créer un réseau :
    > docker network create <name>

.Lister les réseaux :
    > docker network ls


#5 - Docker Compose

Docker Compose permet de construire plusieurs dockers liés dans le bon ordre et
avec les bonnes configurations, gérant ainsi plusieurs dockers en même temps.

.Construire/Reconstruire les images Docker du docker-compose.yml :
    > docker compose -f <configFile> build --no-cache
        -f <configFile> : compose.yaml file
        --no-cache      : ignore le cache des couches de construction.

.Démarrer les services du docker-compose.yml :
    > docker compose -f <configFile> up -d
        -d : "detached", les conteneurs tournent en arrière-plan.

.Lister tous les conteneurs associés au docker-compose.yml :
    > docker compose -f <configFile> ps

.Arrêter et supprimer les conteneurs et réseaux du docker-compose.yml :
    > docker compose -f <configFile> down -v
        -v : demande également la suppression des volumes nommés associés.


#6 - Cache Redis

Permet de garder des données à portée de main pour ne pas avoir à les recréer.
Lorsque'un cache est sollicité, il y a deux options :
    Cache HIT  : les données sont présentes dans Redis. Elles sont renvoyées.
    Cache MISS : les données ne sont pas présentes dans Redis. Il faut les créer.
